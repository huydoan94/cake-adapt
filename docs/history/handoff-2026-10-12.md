## Committed follow-up: MQTT sender fixes (2026-10-12)

Committed as `12046bc` after review (the review's lost-wake-up test gap and
minor items were fixed first), followed by `7a10482`, which moved the bounded
join into `common/helpers` (`thread_join_within`) for the ubus and MQTT threads.
The user approved three fixes from the primary agent's review of
`src/logging/mqtt.c`:

- `mqtt_submit` writes the wake eventfd only when the queue goes from empty to
  non-empty, never for a dropped line. The sender already drains a non-empty
  queue without waiting; publish/connect callbacks still wake it.
- No `pthread_cancel`. Each attempt is a `struct mqtt_connection` (client,
  thread, `stop`/`online`/`pending`), referenced by the sender and its network
  thread; the last reference destroys the client. The sender joins it for at
  most 500 ms (`mqtt_join`, the `publish_join` pattern) and otherwise detaches
  it; the thread also holds a sender-state reference, and the state's last
  owner runs `mosquitto_lib_cleanup` (`mosquitto_lib_init` runs in
  `mqtt_start` on the main thread). No new attempt starts while an earlier
  network thread is alive (`owners > 2`), so at most one is ever left behind.
  `state->online` is the sender's mirror of the current connection, so a late
  callback cannot affect a newer one. A clock failure always reaches the poll.
- Style: local pointers instead of mixed `->`/`.` chains (`mqtt.c`,
  `defaults.c`); `mqtt_start` takes an error buffer naming the failing step.
- Checks (after the review round): `tools/host-test.sh x86`, `check-mqtt`
  (wake, stuck-resolver with one-thread cap and an 8-line batch published
  within 50 ms via callbacks delivered on the mock network thread, and
  stop-while-resolving; about 13 s), ASan/UBSan, TSan under `setarch -R`, x86
  `-fsyntax-only` of the changed daemon sources, and the non-SSL broker
  integration (20-line batch in 3.8 ms, bound 0.5 s), evidence in
  `build/mqtt-validation/evidence-fixes/`. A lost-wake-up mutant (no wake in
  the publish callback, no drain `continue`) fails the batch test. No SDK
  package build or VM run. Committed as `12046bc`.
- Uncommitted refactor after `12046bc` (no behaviour change): the bounded
  join is one helper, `thread_join_within()` in `common/helpers.c` (10 ms
  checks), replacing `mqtt_join` and `publish_join`; if the first clock read
  fails, only the check count bounds it. Unit-tested in `test_helpers`;
  `tools/host-test.sh x86`, `check-mqtt` (plain, TSan) and x86
  `-fsyntax-only` pass. No flowchart references these names. Report:
  `/tmp/cake-adapt-tasks/mqtt-fixes-report.md`.

## Why the earlier build entered kernel targets

The earlier MQTT prototype added `libmosquitto-ssl`, which brings in OpenSSL. The normal
package Make target recursively follows the SDK's generated dependency graph.
In the existing Filogic SDK, `libopenssl-afalg=m` selects `kmod-crypto-user`,
making `openssl/compile` depend on `package/kernel/linux/compile`.
`libopenssl-devcrypto=m` also selects the separate cryptodev kernel module.
The generated graph is in that SDK's `tmp/.packagedeps`; the engine dependencies
are defined in its `feeds/base_root/package/libs/openssl/Makefile`.

`build/mqtt-validation/filogic-build.log` shows entry into `package/kernel/linux`
and 282 `apk mkpkg` commands for kernel-module packages before the job was
stopped. It shows repackaging existing `.ko` files, not a full kernel source or
image compilation. Selecting a kernel-module dependency enters the common
kernel package recipe, which handles many selected module packages. The initial
recursive command was too broad for this validation; final builds used prepared
dependencies and `NO_DEPS=1`, with unneeded OpenSSL engines excluded for those
commands. Do not remove dependencies while still promising the behavior that
requires them.
The initial user-directed non-SSL switch removed TLS support and that OpenSSL
dependency chain; the follow-up restored them only for optional `ssl=yes` builds,
now the `cake-adapt-mqtt-ssl` package variant. The existing SDK's unrelated OpenSSL packages
and historical Filogic outputs have not been removed.
