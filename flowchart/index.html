00 — System and ownership overview

Open SVGDOT source
Important behavior and caveats
  • The pipeline is measurement → controller decision → desired CAKE state → verified kernel update. Each stage lives in its own subsystem directory under src/.
  • The upload direction is the configured interface; download is ifb4<interface>, truncated to the kernel interface-name limit. A complete ul_if/dl_if pair overrides both.
  • fping is the default pinger. irtt is also implemented as a per-reflector child process.
  • Every reflector reply runs the controller once, as in cake-autorate. The traffic timer only refreshes CAKE counters, achieved rates and activity state.

01 — Service, CLI, configuration, and startup

files/cake-adapt.init:start_service:95 files/cake-adapt.init:start_instance:40 files/cake-adapt.init:generate_runtime_config:11 src/main.c:main:214 src/config/config.c:config_load:574 src/config/config.c:resolve_interfaces:267 src/config/validate.c:config_validate:288
Open SVGDOT source
Important behavior and caveats
  • The init script generates a private runtime copy for each instance under /tmp/cake-adapt-config/<section>. It validates that copy with the daemon itself (-V) before procd sees the instance.
  • config_file names a cake-autorate-format Bash file. The importer sources it only in a child process and writes the recognized options into the staged UCI copy.
  • config_load applies built-in defaults first, then reads the typed UCI options, resolves the interface pair, and runs config_validate.
  • A disabled configuration is reported to syslog and exits successfully. An invalid configuration is reported and exits with status 1.
  • Rate control stays opt-in. With both adjust flags off, the daemon runs in observation-only mode.

02 — Monitor initialization and uloop event topology

src/monitor/monitor.c:monitor_run:262 src/monitor/pingers.c:pingers_prepare:529 src/monitor/control.c:control_start:468 src/monitor/reflectors.c:reflectors_start:319 src/monitor/links.c:links_watch_events:423 src/monitor/monitor.c:watch_cpu:216 src/monitor/monitor.c:watch_log_maintenance:234
Open SVGDOT source
Important behavior and caveats
  • All monitor state lives in one struct monitor on monitor_run's stack, split into parts owned by links.c, control.c, pingers.c, reflectors.c and tcpdelay.c. The aggregate initializer zeroes everything that is not set explicitly.
  • control_start converts the per-million UCI factors to cake-autorate's per-thousand and percent rounding.
  • reflectors_start initializes one latency tracker per configured reflector. With randomize_reflectors it shuffles the order using getentropy.
  • The first traffic cycle runs before uloop_run, so CAKE discovery and the first counter baseline happen immediately.
  • Pinger output, pinger exits, qdisc events, timers and SIGUSR1/SIGUSR2 are all uloop callbacks. No thread or polling loop sits outside uloop.

03 — CAKE readiness, traffic counters, and fresh-sample IDs

src/monitor/monitor.c:monitor_tick:118 src/monitor/links.c:links_observe:272 src/monitor/links.c:observe_cake:189 src/cake/cake.c:cake_read_all:209 src/monitor/links.c:observe_traffic:19 src/platform/traffic.c:traffic_update:31 src/platform/traffic.c:traffic_compensated_interval_microseconds:9
Open SVGDOT source
Important behavior and caveats
  • The kernel ignores tcm_ifindex in a qdisc dump, so one dump serves both directions. The interface index is cached and cleared when CAKE is not found.
  • The MTU is read with SIOCGIFMTU only when CAKE is discovered or replaced. Every other tick reuses the cached value.
  • When CAKE is not found, the direction stops dumping until an RTM_NEWQDISC event wakes discovery. A read error retries after interface_up_check_interval_s.
  • Achieved rate = Δbytes × 8000 / Δms, taken from CAKE's own byte counter. A counter reset, a replaced qdisc, or a bad interval re-baselines without producing a rate.
  • traffic_sample_id increases only for a fresh rate. The controller uses it to allow at most one high-load increase per achieved-rate sample, as upstream does.
  • Once both directions report MTU and bandwidth, the timer interval becomes max(configured interval, 10 × the serialization time of both maximum wire packets). This matches upstream compensation.

04 — Kernel qdisc lifecycle events

src/monitor/links.c:handle_qdisc_events:404 src/monitor/links.c:process_qdisc_event:362 src/monitor/links.c:event_direction:329 src/platform/netlink.c:netlink_receive_qdisc_events:158 src/platform/netlink.c:handle_qdisc_event:135
Open SVGDOT source
Important behavior and caveats
  • Only root qdisc events are considered. Events are matched to a direction by the cached interface index.
  • An unknown index falls back to if_nametoindex, which covers a recreated interface (for example a new ifb4<if>). The new index is cached and the MTU is marked for re-reading.
  • A bandwidth change sends RTM_NEWQDISC with the existing handle. It is ignored, so the daemon's own writes never trigger rediscovery.
  • Removing CAKE suspends that direction and stops the pingers. A newly created qdisc triggers an immediate traffic cycle instead of waiting for the next tick.
  • A truncated event payload is rejected before dispatch. A failure on the event socket itself is fatal: lifecycle tracking would otherwise be silently lost.

05 — Pinger process ownership and reply parsing

src/monitor/pingers.c:ensure_latency_open:48 src/latency/fping.c:latency_open:84 src/monitor/pingers.c:watch_started_latency_children:382 src/monitor/pingers.c:handle_pinger_output:299 src/latency/latency.c:latency_next_line:415 src/latency/parser.c:parse_fping_line:196 src/monitor/pingers.c:handle_pinger_exit:344 src/monitor/pingers.c:pingers_close:238
Open SVGDOT source
Important behavior and caveats
  • Pingers start only while both CAKE qdiscs are available. A new session waits until uloop has reaped the previous children, as cake-autorate does before restarting.
  • fping runs as [ping_prefix_string…] /usr/bin/fping [ping_extra_args…] -I <ul_if> --timestamp --loop --period <interval> --interval <interval ÷ targets> --timeout 10000 <targets>. -I is omitted when ping_extra_args already selects an interface.
  • fping RTT is split evenly into download and upload OWD (RTT/2 each). ICMP_TIMESTAMP keeps fping's raw bracketed token for log compatibility.
  • Each child gets its own process group. Stopping sends SIGTERM to the group; a 500 ms timer escalates to SIGKILL.
  • A parse error or an unknown reflector reports latency as degraded once, then restarts from the loop. A stream cannot be freed inside its own read callback.

06 — Per-reflector baseline and delay tracking

src/monitor/pingers.c:process_latency_line:137 src/monitor/reflectors.c:reflectors_record:46 src/latency/tracker.c:tracker_update:112 src/latency/tracker.c:tracker_update_direction:78 src/latency/tracker.c:tracker_update_delta_ewma:156 src/controller/controller.c:controller_low_load:643 src/common/helpers.c:response_timestamp:92
Open SVGDOT source
Important behavior and caveats
  • The baseline starts at 100 ms. It moves by alpha_baseline_increase (0.001) when the sample is at or above it, and by alpha_baseline_decrease (0.9) when below. A rising delay therefore barely moves the baseline, and an improvement is adopted almost at once.
  • delta = OWD − baseline, per direction. The controller sees only this delta.
  • The delta EWMA (alpha 0.095) is used only for reflector comparison. It updates only while both directions are below high_load_thr, using the last load percentage, which is 0 before the first rate sample. This matches upstream.
  • The response timestamp is converted from realtime to monotonic. A reply older than 500 ms still updates baselines and health but does not reach the controller.
  • irtt timestamps can roll over; a detected rollover resets the baseline to the sample and reports a zero delta.

07 — Delay window and congestion classification

src/monitor/control.c:control_update:345 src/monitor/control.c:direction_input:321 src/controller/controller.c:controller_update:506 src/controller/controller.c:update_direction:433 src/controller/controller.c:update_congestion:175 src/controller/controller.c:update_line_state:130
Open SVGDOT source
Important behavior and caveats
  • Every reflector reply feeds both directions into a rolling window of bufferbloat_detection_window (6) samples. Its sum and delayed count are maintained incrementally.
  • A sample counts as delayed when its delta exceeds the compensated delay threshold. A sample keeps the classification it had when it entered the window.
  • Congestion is DETECTED when delayed count ≥ bufferbloat_detection_threshold (3). The average is window sum ÷ window size, so empty slots count as zero.
  • Thresholds include the serialization delay of one maximum wire packet at the current shaper rate (chart 09).
  • The saturated/below-capacity line state (90% enter, 80% exit, 3 samples each) is only logged. Rate decisions do not use it.

08 — Exact per-direction rate decision order

src/controller/controller.c:adjust_rate:316 src/controller/controller.c:set_rate_output:408 src/common/utils.h:interval_elapsed:126 src/common/helpers.c:load_percent:126
Open SVGDOT source
Important behavior and caveats
  • The order matches cake-autorate's update_shaper_rate: a bufferbloat cut first, then a high-load increase, then low-load decay toward base.
  • high load means achieved rate as a percentage of the previous shaper rate > high_load_thr (75%).
  • Refractory comparisons are strict: an interval equal to the refractory period has not elapsed.
  • A congestion cut also restarts the decay clock, so decay cannot immediately undo it. An increase restarts the decay clock too.
  • The first valid sample writes the base rate even when CAKE already holds it, as upstream's first set_shaper_rates does. Both refractory clocks start then.
  • When CAKE differs from the controller's rate with no new decision (an external change), the controller's rate is rewritten and logged as reconcile.

09 — Rate factors, thresholds, rounding, and bounds

src/controller/controller.c:downward_factor:247 src/controller/controller.c:upward_factor:283 src/controller/controller.c:interpolate_factor:225 src/controller/controller.c:scale_rate:14 src/controller/controller.c:rate_toward_base:36 src/controller/controller.c:compensate_direction:582 src/monitor/control.c:control_start:468
Open SVGDOT source
Important behavior and caveats
  • Rates are computed in whole kbit/s and truncated, like upstream's integer shell arithmetic. Factors are per-million: per-thousand endpoints plus three more decimal places from interpolation.
  • Cut: delay ≤ threshold → minimum cut (0.99). Delay ≥ adjust-down maximum → maximum cut (0.75). Linear in between.
  • Increase: delay ≤ adjust-up maximum → maximum increase (1.04). Delay ≥ threshold → minimum increase (1.00). Linear in between.
  • Decay uses 0.99 above base and 1.01 below base, and never crosses base.
  • compensation = serialization time of CAKE's maximum wire packet at the current shaper rate. It is added to all three delay thresholds after every decision.
  • Defaults match cake-autorate: thresholds 10/30/60 ms, high_load_thr 75%, refractory periods 300 ms and 1 s.

10 — CAKE update, bounded netlink, and readback verification

src/monitor/control.c:control_update:345 src/monitor/control.c:apply_bandwidth:271 src/cake/cake.c:cake_set_bandwidth:282 src/platform/netlink.c:netlink_change_qdisc_option:427 src/platform/netlink.c:receive_response:318 src/cake/cake.c:cake_read:266
Open SVGDOT source
Important behavior and caveats
  • The SHAPER record is written before the change, matching upstream's ordering. A direction with adjustment disabled still logs its base rate once at startup, as upstream does.
  • The change targets the existing qdisc by ifindex, handle and parent with only TCA_CAKE_BASE_RATE64 (bytes/s). Other CAKE options are left untouched.
  • Every netlink request shares a single 1 s deadline across all reply parts. EINTR and partial multipart replies cannot extend the wait.
  • The readback reuses the cached ifindex and MTU. The new state is accepted only if CAKE reports exactly the requested bandwidth.
  • A failed change or a mismatching readback is logged as a warning and the previous observation is kept. The next decision reconciles the difference.

11 — RUNNING, IDLE, STALL, and recovery state machine

src/monitor/monitor.c:update_activity:18 src/controller/controller.c:activity_update:678 src/monitor/pingers.c:pingers_resume:507 src/monitor/pingers.c:pingers_restart:521 src/monitor/control.c:control_enforce_minimum:440
Open SVGDOT source
Important behavior and caveats
  • The stall timeout = stall_detection_threshold × (reflector_ping_interval ÷ pingers), measured from the last reflector response.
  • Idle requires enable_sleep_function, valid counters in both directions, and both rates ≤ connection_active_thr for longer than sustained_idle_sleep_thr_s. Entering IDLE stops the pingers.
  • Rates are compared in whole kbit/s, as upstream does. STALL needs both directions at or below the 10 kbit/s stall threshold; any traffic above it keeps RUNNING.
  • After the pingers start (startup, IDLE wake, or CAKE returning) there is a grace of two ping intervals. Stall and reflector checks are skipped during the grace and reflector health restarts at its end.
  • If no response arrives for global_ping_response_timeout_s, the warning is logged once. When minimum_shaper_rates_enforcement is set, minimum rates are applied. Pingers restart at most once per timeout period.
  • Without CAKE in both directions, pingers are suspended and the activity machine does not run.

12 — Reflector health, comparison, and replacement

src/monitor/reflectors.c:handle_health_timer:239 src/monitor/reflectors.c:run_scheduled_reflector_work:197 src/monitor/reflectors.c:compare_active_reflectors:122 src/monitor/reflectors.c:replace_active_reflector:73 src/controller/reflector.c:health_check:54 src/controller/reflector.c:reflector_compare:76 src/controller/reflector.c:reflector_rotate:130
Open SVGDOT source
Important behavior and caveats
  • The health timer (1 s) runs only while both CAKE qdiscs exist, the state is RUNNING, and the pinger grace has ended.
  • Every reflector_replacement_interval_mins (60), one random active reflector is replaced. Otherwise, every reflector_comparison_interval_mins (1), active reflectors are compared.
  • Comparison replaces the first reflector whose baseline sum exceeds the minimum by more than 20 ms, or whose download or upload delta EWMA exceeds the minimum by more than 10 ms.
  • A missed response deadline (1 s) is an offence. Three offences in a 60-check window mark the reflector misbehaving. At most one replacement happens per check cycle.
  • Replacement swaps in the first spare reflector and moves the bad one to the end of the order. Its tracker is discarded unless retain_reflector_stats is set. With no spare, only the offences are reset.
  • fping owns all active targets in one process, so any replacement restarts the pinger session.

13 — Structured logging, CPU sampling, rotation, export, and reset

src/logging/log.c:log_message:800 src/logging/log.c:write_timed_record:577 src/logging/log.c:log_tick:316 src/logging/log.c:rotate_log_file:288 src/logging/log.c:log_export_file:228 src/logging/log.c:log_reset_file:268 src/monitor/monitor.c:handle_cpu_timer:173
Open SVGDOT source
Important behavior and caveats
  • Record names, field order, units and headers follow cake-autorate's DATA, LOAD, REFLECTOR, SUMMARY, SHAPER and CPU formats so its analysis tools work on cake-adapt logs.
  • Syslog receives errors, warnings and the start, stop and disabled messages. Debug messages go there only with log_debug_messages_to_syslog. Every message also goes to the log file when one is open.
  • The local date and time text is formatted once per second and reused. The file uses a 16 KiB stdio buffer flushed by the log timer every log_file_buffer_timeout_ms.
  • Rotation copies the active log to cake-adapt[.<section>].log.old and truncates the active file in place. The inode is preserved, so tail -f stays attached.
  • SIGUSR1 exports the active and retained logs (optionally compressed with zlib). SIGUSR2 flushes and truncates them in place.
  • CPU records are written only while RUNNING. A failed /proc/stat read is reported once as degraded and once on recovery.

14 — Shutdown, failure severity, and cleanup ownership

src/monitor/monitor.c:monitor_run:262 src/monitor/pingers.c:pingers_stop_now:254 src/latency/latency.c:latency_stop_now:400 src/latency/latency.c:stop_child:46 src/monitor/reflectors.c:reflectors_stop:384 src/main.c:main:214
Open SVGDOT source
Important behavior and caveats
  • procd stops the instance with SIGTERM and allows 5 s. uloop_run returns the signal number, and SIGINT or SIGTERM count as a clean shutdown.
  • After the loop stops, pinger shutdown is synchronous and bounded: SIGTERM to each process group, up to 50 × 10 ms waitpid checks, then SIGKILL and a final reap.
  • Fatal conditions: invalid configuration, controller, tracker or health allocation failure, uloop or required timer setup, qdisc event subscription, and qdisc event socket failure.
  • Degraded but continuing: missing CAKE or interface, netlink dump or change failures, pinger spawn, exit or parse failures, clock failures, CPU sampling, and log maintenance. Each is logged once and again on recovery.
  • The daemon never removes or recreates CAKE, and leaves the last verified rate in place on exit.

15 — Worked example: 20 Mbit/s under load with a delay burst

src/controller/controller.c:adjust_rate:316 src/controller/controller.c:upward_factor:283 src/controller/controller.c:downward_factor:247 src/controller/controller.c:scale_rate:14
Open SVGDOT source
Important behavior and caveats
  • Inputs: cake-autorate defaults; minimum/base/maximum 10/20/50 Mbit/s; a 12,000-bit maximum wire packet; one reply every 50 ms. Download is at 19 Mbit/s (95% of the shaper, so high load) throughout.
  • Every number here was produced by running the real controller (controller.c) on these inputs. The replay test checks the same arithmetic against recorded cake-autorate traces.
  • With 12,000 bits at 20 Mbit/s, compensation is 600 µs and the thresholds become 10.6, 30.6 and 60.6 ms. They are recomputed at each new shaper rate.
  • No increase happens before 350 ms: the initial write starts the bufferbloat refractory clock, and the comparison is strict.
  • The cut uses the minimum factor because the window average (25.0 ms) is still below the delay threshold. The 6-slot average lags the instantaneous delay.
  • Further cuts would need another 300 ms. The window clears at 1.80 s, so only one cut happens and increases resume.
