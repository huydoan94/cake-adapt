00 — System and ownership overview

Important behavior and caveats
  • The pipeline is measurement → controller decision → desired CAKE state → verified kernel update. Each stage lives in its own subsystem directory under src/.
  • The upload direction is the configured interface; download is ifb4<interface>, truncated to the kernel interface-name limit. A complete ul_if/dl_if pair overrides both.
  • The daemon's own ICMP probes (native, native-ts) are the default pinger. fping, fping-ts and irtt remain as fallbacks, run as child processes.
  • Every reflector reply runs the controller once, as in cake-autorate. The traffic timer only refreshes CAKE counters, achieved rates and activity state.

01 — Service, CLI, configuration, and startup

files/cake-adapt.init:start_service:186 files/cake-adapt.init:start_instance:115 files/cake-adapt.init:generate_runtime_config:18 files/cake-adapt.init:register_instance:88 files/cake-adapt.init:keep_instance:107 files/cake-adapt.init:reload_service:260 files/cake-adapt.init:stop_service:238 src/main.c:main:265 src/main.c:lock_instance:142 src/config/config.c:config_load:553 src/config/config.c:resolve_interfaces:236 src/config/validate.c:config_validate:363 src/logging/mqtt.c:mqtt_start:310 src/logging/mqtt_none.c:mqtt_start:12
Open SVGDOT source
Important behavior and caveats
  • The init script generates a private runtime file for each instance, /var/run/cake-adapt/<section>.uci. It builds and validates it with the daemon itself (-V) in a staging directory, then moves it into place before procd sees the instance, which runs with -C pointing at that file. As in dnsmasq, procd watches that generated file, and reload registers the instances again without stopping anything: procd restarts only an instance whose command or runtime file changed, and stops instances no longer registered (removed or disabled sections). A configuration that fails to build or validate leaves the previous runtime file in place, so the instance is registered unchanged and keeps running; with no previous file (a first start, or after stop, which removes it) the instance does not start. restart checks each requested instance's new configuration first: a valid one stops the instance and starts it again (new pid, even if unchanged); a refused one keeps it running its previous file, as on a reload; a named restart of a disabled or removed section stops it and removes its file, and an instance procd could not stop is logged and fails the restart. start, stop and restart take an optional section name and then act on that instance only. Each instance is registered with respawn 3600 5 0: procd starts an exited instance again after 5 s and never gives up (retry 0).
  • config_file names a cake-autorate-format Bash file. It, ping_prefix_string, ping_extra_args and log_file_path_override make root run something, choose its arguments or choose where it writes, so the importer reads them only from the root-only /etc/cake-adapt/exec, which LuCI cannot write; any of them set in /etc/config/cake-adapt refuses the import. The importer is plain sh; a separate Bash reader sources the file in a child process, and the importer writes the recognized options the UCI section leaves unset into the staged UCI copy: UCI wins.
  • config_load applies built-in defaults first, then reads the typed UCI options, resolves the interface pair, and runs config_validate.
  • A disabled configuration is reported to syslog and exits successfully. An invalid configuration is reported and exits with status 1.
  • Before the log file, main takes an exclusive non-blocking lock on /var/run/cake-adapt/<section>.lock and writes its pid there. A second daemon with a running instance's name logs "instance '<section>' is already running (pid N); exiting" and exits with status 1; the first keeps running. The kernel releases the lock when the process exits, so procd respawn and restart work. -V and -L take no lock.
  • Rate control stays opt-in. With both adjust flags off, the daemon runs in observation-only mode.
  • After opening the instance log file, main starts the optional MQTT sender before startup records. MQTT defaults off and its configuration is validated with the other UCI settings. Network failures do not stop the daemon. In the cake-adapt package (no MQTT) a start with mqtt_enabled on fails and main logs "MQTT logging degraded: ..." as a warning; the instance runs and controls as usual.

02 — Monitor initialization and uloop event topology

src/monitor/monitor.c:monitor_run:300 src/monitor/pingers.c:pingers_prepare:668 src/monitor/control.c:control_start:472 src/monitor/reflectors.c:reflectors_start:361 src/monitor/links.c:links_watch_events:433 src/monitor/publish.c:publish_start:427 src/monitor/publish.c:publish_thread:334 src/monitor/publish.c:publish_status:176 src/monitor/status.c:status_snapshot:29 src/monitor/monitor.c:watch_cpu:209 src/monitor/monitor.c:watch_log_maintenance:263
Open SVGDOT source
Important behavior and caveats
  • All monitor state lives in one struct monitor on monitor_run's stack, split into parts owned by links.c, control.c, pingers.c, reflectors.c, tcpdelay.c and publish.c. The aggregate initializer zeroes everything that is not set explicitly.
  • control_start copies the UCI settings into the controller configuration unchanged: ratios per million, durations in microseconds and rates in bit/s.
  • reflectors_start initializes one latency tracker per configured reflector. With randomize_reflectors it shuffles the order using getentropy.
  • The first traffic cycle runs before uloop_run, so CAKE discovery and the first counter baseline happen immediately.
  • publish_start, after uloop_init, starts one thread with every signal blocked. It owns its own ubus context, never added to uloop, so libubus calls that can block without a timeout on a stalled ubusd block only that thread. It handles each ubus state as dnsmasq does: no ubusd is retried every second; a lost connection is reconnected at once (re-adding the object) or closed and retried; POLLHUP or POLLERR closes and retries; a refused object ends the run when it happens on the first connection and otherwise ends the attempts. publish.c:publish_status answers on that thread from the snapshot the main thread copies in on every traffic tick (chart 03).
  • Pinger output, pinger exits, qdisc events, timers and SIGUSR1/SIGUSR2 are all uloop callbacks on the main thread. The ubus thread is the only other thread; it never calls into the monitor and never logs: it raises event bits that the main thread logs.

03 — CAKE readiness, traffic counters, and fresh-sample IDs

src/monitor/monitor.c:monitor_tick:111 src/monitor/monitor.c:handle_traffic_timer:130 src/monitor/links.c:links_observe:268 src/monitor/links.c:observe_cake:189 src/cake/cake.c:cake_read:231 src/monitor/links.c:observe_traffic:20 src/platform/traffic.c:traffic_update:22 src/platform/traffic.c:traffic_compensated_interval_us:9 src/monitor/publish.c:publish_update:493
Open SVGDOT source
Important behavior and caveats
  • The kernel ignores tcm_ifindex in a qdisc dump, so one dump serves both directions. The interface index is cached and cleared when CAKE is not found.
  • The MTU is read with SIOCGIFMTU only when CAKE is discovered or replaced. Every other tick reuses the cached value.
  • When CAKE is not found, the direction stops dumping until an RTM_NEWQDISC event wakes discovery. A read error retries after interface_up_check_interval_s.
  • Achieved rate = Δbytes × 8000 / Δms, taken from CAKE's own byte counter. A counter reset, a replaced qdisc, or a bad interval re-baselines without producing a rate.
  • traffic_sample_id increases only for a fresh rate. The controller uses it to allow at most one high-load increase per achieved-rate sample, as upstream does.
  • Once both directions report MTU and bandwidth, the timer interval becomes max(configured interval, 10 × the serialization time of both maximum wire packets). This matches upstream compensation.
  • After every tick, ready or not, publish_update copies status_snapshot into the ubus thread's shared state under a mutex and logs the events the thread raised since, with dnsmasq's levels: no connection (once until connected), connected after a failed attempt, cannot reconnect, disconnecting, and ubus errors. An object refused on the first connection logs the error and ends the run with result -1 (chart 14).

04 — Kernel qdisc lifecycle events

src/monitor/links.c:handle_qdisc_events:413 src/monitor/links.c:process_qdisc_event:367 src/monitor/links.c:event_direction:330 src/platform/netlink.c:netlink_receive_qdisc_events:149 src/platform/netlink.c:handle_qdisc_event:127
Open SVGDOT source
Important behavior and caveats
  • Only root qdisc events are considered. Events are matched to a direction by the cached interface index.
  • An unknown index falls back to if_nametoindex, which covers a recreated interface (for example a new ifb4<if>). The new index is cached and the MTU is marked for re-reading.
  • A bandwidth change sends RTM_NEWQDISC with the existing handle. It is ignored, so the daemon's own writes never trigger rediscovery.
  • Removing CAKE suspends that direction and stops the pingers. A newly created qdisc triggers an immediate traffic cycle instead of waiting for the next tick.
  • A truncated event payload is rejected before dispatch. A failure on the event socket itself is fatal: lifecycle tracking would otherwise be silently lost.

Important behavior and caveats
  • Pingers start only while both CAKE qdiscs are available. A new session waits until uloop has reaped the previous children, as cake-autorate does before restarting. Native probes own sockets and timers, with no child processes.
  • native/native-ts are opt-in pending the live comparison. Numeric addresses only; no prefix or extra arguments. Requests expire after 10 s. Delayed timers send once rather than catching up; reply callbacks process at most 64 datagrams.
  • fping runs as [ping_prefix_string…] /usr/bin/fping [ping_extra_args…] -I <ul_if> --timestamp --loop --period <interval> --interval <interval ÷ targets> --timeout 10000 <targets>. -I is omitted when ping_extra_args already selects an interface.
  • fping RTT is split evenly into download and upload OWD (RTT/2 each). ICMP_TIMESTAMP keeps fping's raw bracketed token for log compatibility.
  • Each child gets its own process group. Stopping sends SIGTERM to the group; a 500 ms timer escalates to SIGKILL.
  • A parse error or an unknown reflector reports latency as degraded once, then restarts from the loop. A stream cannot be freed inside its own read callback.

06 — Per-reflector baseline and delay tracking

src/monitor/pingers.c:process_latency_sample:120 src/monitor/reflectors.c:reflectors_record:98 src/latency/tracker.c:tracker_update:92 src/latency/tracker.c:tracker_update_direction:66 src/latency/tracker.c:tracker_update_delta_ewma:129 src/controller/controller.c:controller_low_load:613 src/common/helpers.c:response_monotonic_us:101 src/common/helpers.c:response_stale:119
Open SVGDOT source
Important behavior and caveats
  • The baseline starts at 100 ms. It moves by alpha_baseline_increase (0.001) when the sample is at or above it, and by alpha_baseline_decrease (0.9) when below. A rising delay therefore barely moves the baseline, and an improvement is adopted almost at once.
  • delta = OWD − baseline, per direction. The controller sees only this delta.
  • The delta EWMA (alpha 0.095) is used only for reflector comparison. It updates only while both directions are below high_load_thr, using the last load ratio, which is 0 before the first rate sample. This matches upstream.
  • The response timestamp is converted from realtime to monotonic. A reply older than 500 ms still updates baselines and health but does not reach the controller.
  • irtt timestamps can roll over; a detected rollover resets the baseline to the sample and reports a zero delta.

07 — Delay window and congestion classification

src/monitor/control.c:control_update:324 src/monitor/control.c:direction_input:301 src/controller/controller.c:controller_update:495 src/controller/controller.c:update_direction:405 src/controller/controller.c:update_congestion:175 src/controller/controller.c:update_line_state:130
Open SVGDOT source
Important behavior and caveats
  • Every reflector reply feeds both directions into a rolling window of bufferbloat_detection_window (6) samples. Its sum and delayed count are maintained incrementally.
  • A sample counts as delayed when its delta exceeds the compensated delay threshold. A sample keeps the classification it had when it entered the window.
  • Congestion is DETECTED when delayed count ≥ bufferbloat_detection_threshold (3). The average is window sum ÷ window size, so empty slots count as zero.
  • Thresholds include the serialization delay of one maximum wire packet at the current shaper rate (chart 09).
  • The saturated/below-capacity line state (90% enter, 80% exit, 3 samples each) is only logged. Rate decisions do not use it.

08 — Exact per-direction rate decision order

src/controller/controller.c:adjust_rate:301 src/controller/controller.c:set_rate_output:381 src/common/utils.h:interval_elapsed:211 src/common/helpers.h:load_ratio_e6:70
Open SVGDOT source
Important behavior and caveats
  • The order matches cake-autorate's update_shaper_rate: a bufferbloat cut first, then a high-load increase, then low-load decay toward base.
  • high load means achieved rate ÷ previous shaper rate, as a ratio per million, > high_load_thr (75%).
  • Refractory comparisons are strict: an interval equal to the refractory period has not elapsed.
  • A congestion cut also restarts the decay clock, so decay cannot immediately undo it. An increase restarts the decay clock too.
  • The first valid sample writes the base rate even when CAKE already holds it, as upstream's first set_shaper_rates does. Both refractory clocks start then.
  • When CAKE differs from the controller's rate with no new decision (an external change), the controller's rate is rewritten and logged as reconcile.

09 — Rate factors, thresholds, rounding, and bounds

src/controller/controller.c:downward_factor_e6:244 src/controller/controller.c:upward_factor_e6:263 src/controller/controller.c:interpolate_factor_e6:227 src/controller/controller.c:scale_rate:15 src/controller/controller.c:rate_toward_base:32 src/controller/controller.c:compensate_direction:558 src/monitor/control.c:control_start:472
Open SVGDOT source
Important behavior and caveats
  • Rates are bit/s and factors are ratios per million (1,000,000 = 1.0), computed exactly. A scaled rate is truncated to whole bytes/s (a multiple of 8 bit/s), the precision CAKE holds. cake-autorate truncates to whole kbit/s and its factors to per-thousand steps; cake-adapt does not copy those truncations.
  • Cut: delay ≤ threshold → minimum cut (0.99). Delay ≥ adjust-down maximum → maximum cut (0.75). Linear in between.
  • Increase: delay ≤ adjust-up maximum → maximum increase (1.04). Delay ≥ threshold → minimum increase (1.00). Linear in between.
  • Decay uses 0.99 above base and 1.01 below base, and never crosses base.
  • compensation = serialization time of CAKE's maximum wire packet at the current shaper rate. It is added to all three delay thresholds after every decision.
  • Defaults match cake-autorate: thresholds 10/30/60 ms, high_load_thr 75%, refractory periods 300 ms and 1 s.

10 — CAKE update, bounded netlink, and readback verification

src/monitor/control.c:control_update:324 src/monitor/control.c:apply_bandwidth:247 src/cake/cake.c:cake_set_bandwidth:288 src/platform/netlink.c:netlink_change_qdisc:415 src/platform/netlink.c:receive_response:306 src/cake/cake.c:cake_read:231
Open SVGDOT source
Important behavior and caveats
  • The SHAPER record is written before the change, matching upstream's ordering. A direction with adjustment disabled still logs its base rate once at startup, as upstream does.
  • The change targets the existing qdisc by ifindex, handle and parent with only TCA_CAKE_BASE_RATE64 (bytes/s). Other CAKE options are left untouched.
  • Every netlink request shares a single 1 s deadline across all reply parts. EINTR and partial multipart replies cannot extend the wait.
  • The readback reuses the cached ifindex and MTU. The new state is accepted only if CAKE reports exactly the requested bandwidth.
  • A failed change or a mismatching readback is logged as a warning and the previous observation is kept. The next decision reconciles the difference.

11 — RUNNING, IDLE, STALL, and recovery state machine

src/monitor/monitor.c:update_activity:20 src/controller/controller.c:activity_update:659 src/monitor/pingers.c:pingers_resume:646 src/monitor/pingers.c:pingers_restart:660 src/monitor/control.c:control_enforce_minimum:434
Open SVGDOT source
Important behavior and caveats
  • The stall timeout = stall_detection_threshold × (reflector_ping_interval ÷ pingers), measured from the last reflector response.
  • Idle requires enable_sleep_function, valid counters in both directions, and both rates ≤ connection_active_thr for longer than sustained_idle_sleep_thr_s. Entering IDLE stops the pingers.
  • Rates are compared in bit/s. STALL needs both directions at or below the 10 kbit/s stall threshold; any traffic above it keeps RUNNING.
  • After the pingers start (startup, IDLE wake, or CAKE returning) there is a grace of two ping intervals. Stall and reflector checks are skipped during the grace and reflector health restarts at its end.
  • If no response arrives for global_ping_response_timeout_s, the warning is logged once. When minimum_shaper_rates_enforcement is set, minimum rates are applied. Pingers restart at most once per timeout period.
  • Without CAKE in both directions, pingers are suspended and the activity machine does not run.

12 — Reflector health, comparison, and replacement

src/monitor/reflectors.c:handle_health_timer:282 src/monitor/reflectors.c:run_scheduled_reflector_work:245 src/monitor/reflectors.c:compare_active_reflectors:178 src/monitor/reflectors.c:replace_active_reflector:128 src/controller/reflector.c:health_check:45 src/controller/reflector.c:reflector_compare:67 src/controller/reflector.c:reflector_rotate:115
Open SVGDOT source
Important behavior and caveats
  • The health timer (1 s) runs only while both CAKE qdiscs exist, the state is RUNNING, and the pinger grace has ended.
  • Every reflector_replacement_interval_mins (60), one random active reflector is replaced. Otherwise, every reflector_comparison_interval_mins (1), active reflectors are compared.
  • Comparison replaces the first reflector whose baseline sum exceeds the minimum by more than 20 ms, or whose download or upload delta EWMA exceeds the minimum by more than 10 ms.
  • A missed response deadline (1 s) is an offence. Three offences in a 60-check window mark the reflector misbehaving. At most one replacement happens per check cycle.
  • Replacement swaps in the first spare reflector and moves the bad one to the end of the order. Its tracker is discarded unless retain_reflector_stats is set. With no spare, only the offences are reset.
  • fping owns all active targets in one process, so any replacement restarts the pinger session.

13 — Structured logging, CPU sampling, rotation, export, and reset

src/logging/log.c:log_message:1313 src/logging/log.c:write_timed_record:992 src/logging/log.c:log_tick:415 src/logging/log.c:rotate_log_file:374 src/logging/log.c:log_export_file:314 src/logging/log.c:log_reset_file:354 src/logging/log.c:queue_entry:523 src/logging/log.c:writer_thread:655 src/monitor/monitor.c:handle_cpu_timer:170 src/logging/mqtt.c:mqtt_submit:382 src/logging/mqtt.c:mqtt_thread:248 src/logging/mqtt.c:mqtt_network:129
Open SVGDOT source
Important behavior and caveats
  • Record names, field order, units and headers follow cake-autorate's DATA, LOAD, REFLECTOR, SUMMARY, SHAPER and CPU formats so its analysis tools work on cake-adapt logs.
  • Syslog receives errors, warnings and the start, stop and disabled messages. Debug messages go there only with log_debug_messages_to_syslog. Every message also goes to the log file when one is open.
  • A writer thread, started once the log file is open, does every write to the log file, stdout and syslog, with rotation, export and reset. The main loop only formats a record and copies it into a 128 KiB queue, so slow storage or a stuck logd never holds up measurement and control. The queue is a bounded FIFO: when it is full, the oldest waiting lines make room for the new one and are counted, and the writer logs the count before the oldest line it still has. An overwritten export or reset request is still carried out. At stop the writer drains the queue for up to 2 s; a writer still stuck in syslog is left behind. Configuration checks (-V) and the unit tests write directly, without the thread.
  • The local date and time text is formatted once per second and reused. The file uses a 16 KiB stdio buffer that the writer flushes every log_file_buffer_timeout_ms.
  • Rotation copies the active log to cake-adapt[.<section>].log.old and truncates the active file in place. The inode is preserved, so tail -f stays attached.
  • SIGUSR1 exports the active and retained logs (optionally compressed with zlib). SIGUSR2 flushes and truncates them in place. Both are queued to the writer, in order with the lines around them, so a long compressed export does not pause the main loop.
  • CPU records are written only while RUNNING. A failed /proc/stat read is reported once as degraded and once on recovery.
  • MQTT is an independent opt-in sink for generated records. The logging thread uses a try-lock to copy into a bounded 32-record queue; offline, full or contended queues drop silently. Sender and network threads handle QoS 0 delivery without retention, a five-second connection deadline, and ten-second retries indefinitely. Only the cake-adapt-mqtt-ssl package can enable TLS: the sender loads the CA file and configures certificate/hostname verification before starting the network thread; the other packages reject TLS settings. The cake-adapt package is built with logging/mqtt_none.c instead: no libmosquitto, nothing is queued or sent. Existing output and debug flags still govern which records are generated.

14 — Shutdown, failure severity, and cleanup ownership

src/monitor/monitor.c:monitor_run:300 src/monitor/pingers.c:pingers_stop_now:245 src/latency/latency.c:latency_stop_now:415 src/latency/latency.c:stop_child:46 src/monitor/publish.c:publish_stop:504 src/monitor/publish.c:publish_update:493 src/monitor/reflectors.c:reflectors_stop:416 src/main.c:main:265 src/logging/mqtt.c:mqtt_stop:406
Open SVGDOT source
Important behavior and caveats
  • procd stops the instance with SIGTERM and allows 5 s. uloop_run returns the signal number, and SIGINT or SIGTERM count as a clean shutdown.
  • publish_stop sets the thread's stop flag, wakes it through an eventfd and joins it for at most 2 s. A thread stuck inside libubus on a frozen ubusd is detached with a warning, and its shared state is deliberately leaked as the process exits.
  • After the loop stops, pinger shutdown is synchronous and bounded: SIGTERM to each process group, up to 50 × 10 ms waitpid checks, then SIGKILL and a final reap.
  • Fatal conditions: invalid configuration, controller, tracker or health allocation failure, uloop or required timer setup, qdisc event subscription, qdisc event socket failure, and ubusd refusing the status object on the first connection (as dnsmasq exits then; procd respawns the daemon every 5 s without limit).
  • Degraded but continuing: missing CAKE or interface, netlink dump or change failures, pinger spawn, exit or parse failures, clock failures, CPU sampling, and log maintenance. Each is logged once and again on recovery.
  • The daemon never removes or recreates CAKE, and leaves the last verified rate in place on exit.
  • log_close stops the optional MQTT sender. It wakes the worker and waits at most about one second; a stuck worker is detached and retains its state until it exits. Queued MQTT records are discarded at shutdown.

15 — Worked example: 20 Mbit/s under load with a delay burst

src/controller/controller.c:adjust_rate:301 src/controller/controller.c:upward_factor_e6:263 src/controller/controller.c:downward_factor_e6:244 src/controller/controller.c:scale_rate:15
Open SVGDOT source
Important behavior and caveats
  • Inputs: cake-autorate defaults; minimum/base/maximum 10/20/50 Mbit/s; a 12,000-bit maximum wire packet; one reply every 50 ms. Download is at 19 Mbit/s (95% of the shaper, so high load) throughout.
  • Every number here was produced by running the real controller (controller.c) on these inputs. The replay test checks the same arithmetic against recorded cake-autorate traces, within its tolerances for cake-autorate's truncations.
  • With 12,000 bits at 20 Mbit/s, compensation is 600 µs and the thresholds become 10.6, 30.6 and 60.6 ms. They are recomputed at each new shaper rate.
  • No increase happens before 350 ms: the initial write starts the bufferbloat refractory clock, and the comparison is strict.
  • The cut uses the minimum factor because the window average (25.0 ms) is still below the delay threshold. The 6-slot average lags the instantaneous delay.
  • Further cuts would need another 300 ms. The window clears at 0.80 s, so only one cut happens and increases resume.
