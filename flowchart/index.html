00 — System and ownership overview

Open SVGDOT source
Important behavior and caveats
  • The daemon adapts CAKE instances that already exist. SQM still creates WAN/IFB, ingress redirect, and qdiscs.
  • The policy boundary is measurement → controller decision → desired CAKE state → verified kernel update.
  • Upload is the configured interface; download is derived as ifb4.
  • fping is the only supported pinger. Configuration comes from typed UCI, optionally followed by safely parsed cake-autorate overrides.

01 — Service, CLI, configuration, and startup

files/cake-adapt.init:1 src/main.c:main:72 src/config.c:config_load:1880 src/config.c:load_section:1417
Open SVGDOT source
Important behavior and caveats
  • procd checks enabled before starting. If the daemon is invoked while disabled, it reports that state and exits successfully.
  • Precedence is built-in defaults < typed UCI < recognized values in the explicitly selected cake-autorate file. The shell file is parsed as data and never executed.
  • The imported ul_if overrides interface; dl_if must match derived ifb4. enabled and the import path remain UCI-owned.
  • Adjustment is independently opt-in for download and upload. Invalid ranges or missing required values prevent control from starting.
  • Log-file setup happens after configuration so the configured path, rotation, export, and record selections can be honored.

02 — Monitor initialization and uloop event topology

src/monitor.c:monitor_run:1866 src/monitor.c:handle_traffic_timer:332 src/monitor.c:handle_latency_output:1180 src/monitor.c:handle_qdisc_events:1149
Open SVGDOT source
Important behavior and caveats
  • One controller direction is initialized for download and one for upload. Their desired rates begin at configured base rates.
  • A tracker exists for every configured reflector; health history exists for each active pinger slot.
  • Qdisc subscription occurs before initial discovery, preventing a lifecycle gap between discovery and event listening.
  • Traffic and health timers are required; optional CPU/log timers degrade with a warning if unavailable.

03 — CAKE readiness, traffic counters, and fresh-sample IDs

src/monitor.c:observe_cake:223 src/monitor.c:cake_ready:334 src/traffic.c:traffic_update:11 src/cake.c:cake_read:236
Open SVGDOT source
Important behavior and caveats
  • A direction can be AVAILABLE, NOT_FOUND, or FAILED. NOT_FOUND waits for an RTM_NEWQDISC event; FAILED is retried on a bounded timer.
  • A usable achieved-rate sample requires a previous baseline, unchanged qdisc identity, nondecreasing counter, and positive elapsed time.
  • The baseline is advanced even for invalid samples so resets and qdisc replacements recover cleanly.
  • Only a computed RATES sample increments traffic_sample_id. The controller uses this ID to prevent repeated upward increases from one traffic sample.

04 — Kernel qdisc lifecycle events

src/monitor.c:handle_qdisc_events:1149 src/monitor.c:process_qdisc_event:1098 src/netlink.c:netlink_subscribe_qdiscs:112
Open SVGDOT source
Important behavior and caveats
  • Lifecycle is event-driven through RTM_NEWQDISC and RTM_DELQDISC; startup_wait_s is intentionally absent.
  • A NEW event for the currently cached handle is ignored because the daemon’s own bandwidth changes also emit NEWQDISC.
  • A disappearance stops latency probing immediately. Reappearance triggers an immediate CAKE/traffic refresh rather than waiting for the periodic timer.

05 — fping process ownership and reply parsing

src/latency.c:latency_open:336 src/latency.c:latency_receive:896 src/latency.c:stop_child:213 src/monitor.c:ensure_latency_open:869
Open SVGDOT source
Important behavior and caveats
  • One owned fping child probes all currently active reflectors. Changing the active set restarts that child.
  • The pipe is nonblocking and integrated into uloop. Operations and shutdown are bounded; the daemon never waits forever for fping.
  • A timeout line is not a latency sample. It is consumed while reflector health detects missing responses by monotonic age.
  • Malformed/full lines, EOF, or read failure degrade probing, close the child, and schedule a retry; they do not kill the daemon.

06 — Per-reflector baseline and delay tracking

src/latency.c:tracker_update:684 src/monitor.c:receive_latency_samples:959 src/controller.c:controller_update:598
Open SVGDOT source
Important behavior and caveats
  • RTT is converted to one-way delay as floor(RTT/2). This is an estimate, not a truly directional measurement.
  • Baseline EWMA follows decreases quickly (α=0.9) and increases slowly (α=0.001). Delta is current OWD minus the updated baseline.
  • Reflector delta EWMA (α=0.095) updates only when both upload and download are at or below the high-load threshold.
  • The same measured latency is supplied to download and upload policy; direction-specific congestion decisions differ through load and thresholds.

07 — Delay window and congestion classification

src/controller.c:update_congestion:253 src/controller.c:update_line_state:194 src/controller.c:controller_update:598
Open SVGDOT source
Important behavior and caveats
  • Each direction keeps a six-entry delay-delta window across reflector replies. Entries begin at zero and the average always divides by six.
  • A reply is delayed when its delta exceeds the direction delay threshold (default 30 ms). Congestion needs at least three delayed entries.
  • Diagnostic line saturation uses a separate 3-observation hysteresis: saturated at >=90% load; recovered at <=80%.
  • Rate high-load classification uses the configured high_load_thr (default 75%) relative to the previous desired rate.

08 — Exact per-direction rate decision order

src/controller.c:update_direction:555 src/controller.c:controller_update:598
Open SVGDOT source
Important behavior and caveats
  • This order matters: congestion reduction can react on every qualifying latency reply, while upward growth requires a fresh traffic_sample_id.
  • A successful upward attempt records the decay clock even when max-rate clamping makes the effective rate unchanged.
  • Low-load decay moves the desired rate toward base by 1% no more than once per second and never crosses base.
  • All outcomes are clamped to min/max. Observation-only directions compute state but never request a kernel rate change.

09 — Rate factors, thresholds, rounding, and bounds

src/controller.c:upward_factor:372 src/controller.c:downward_factor:328 src/controller.c:scale_rate:21
Open SVGDOT source
Important behavior and caveats
  • A is the six-sample average OWD delta. U is adjust-up threshold, D is per-sample delay threshold, and L is maximum adjust-down threshold.
  • Configured floating factors are represented as integers to avoid floating-point policy drift. Rates are whole kbit/s.
  • Defaults are U=10 ms, D=30 ms, L=60 ms; maximum upward factor 1.04; maximum downward reduction 25%.
  • There is currently no fixed “achieved throughput minus 5 Mbps” reserve, learned-capacity estimate, or 170 Mbps target. Adding one is a new policy design.

10 — CAKE update, bounded netlink, and readback verification

src/monitor.c:apply_bandwidth:661 src/cake.c:cake_set_bandwidth:270 src/cake.c:cake_read:236 src/netlink.c:netlink_change_qdisc_option:556
Open SVGDOT source
Important behavior and caveats
  • No tc process is spawned. The tc-like SHAPER log is explanatory; the actual operation is rtnetlink.
  • kbit/s is converted to CAKE’s bytes/s attribute with checked arithmetic. Existing qdisc handle and parent are preserved.
  • The request socket waits at most one second for ACK/replies; EINTR does not extend the deadline.
  • The cached effective rate changes only after a readback confirms the requested bandwidth. Failure is nonfatal and later replies can reconcile it.

11 — RUNNING, IDLE, STALL, and recovery state machine

src/monitor.c:update_monitor_state:1306 src/controller.c:activity_update:664 src/monitor.c:close_latency:1055 src/monitor.c:enforce_minimum_rates:1237
Open SVGDOT source
Important behavior and caveats
  • Defaults: idle threshold 2 Mbit/s, idle duration 60 s, stall-load bypass 10 kbit/s, response timeout roughly 250 ms, global failure 10 s.
  • IDLE stops fping. It wakes when either valid traffic direction exceeds the idle threshold, resets response clocks, and grants two ping periods of grace.
  • STALL represents missing reflector replies while traffic is not clearly active. If both directions exceed the stall-load threshold, the daemon stays RUNNING.
  • After global response failure, enabled directions may be forced to minimum rate and fping is restarted no more often than every 10 seconds.

12 — Reflector health, comparison, and replacement

src/monitor.c:handle_reflector_health_timer:1764 src/monitor.c:replace_active_reflector:1436 src/monitor.c:run_scheduled_reflector_work:1707
Open SVGDOT source
Important behavior and caveats
  • Health runs once per second only while RUNNING, both qdiscs are available, and wake grace has expired.
  • Scheduled randomization defaults to every 60 minutes. Statistical comparison defaults to every minute.
  • A reflector is comparatively poor when its doubled baseline exceeds the best by >20 ms or its delta EWMA exceeds the best by >10 ms.
  • Missing responses count as offenses after 1 second; three offenses in the 60-check ring mark a reflector misbehaving. At most one replacement occurs per health tick.

13 — Structured logging, CPU sampling, rotation, export, and reset

src/log.c:1 src/cpu.c:1 src/monitor.c:handle_log_export_signal:1595 src/monitor.c:handle_log_reset_signal:1609
Open SVGDOT source
Important behavior and caveats
  • High-frequency record groups are optional. System messages still expose startup, shutdown, invalid config, missing qdisc/interface, fping/netlink failures, and degraded operation.
  • Rotation copies the live file to .old and truncates the live file in place, preserving inode continuity for tail -f.
  • SIGUSR1 exports old+live logs to a timestamped artifact (optionally gzip). SIGUSR2 truncates/reset files in place and rewrites headers.
  • CPU sampling is optional and occurs only in RUNNING. CPU-count changes reset its baseline and header; read failure warns and can recover.

14 — Shutdown, failure severity, and cleanup ownership

src/main.c:main:72 src/monitor.c:monitor_run:1866 src/latency.c:latency_close:645 src/netlink.c:1
Open SVGDOT source
Important behavior and caveats
  • SIGINT/SIGTERM is an orderly success path. A fatal uloop/netlink state returns failure only when continuing would be incorrect.
  • One optional measurement failure does not terminate the daemon. Available directions continue and degraded state is reported.
  • Shutdown does not delete SQM-created interfaces/qdiscs and does not restore previous CAKE rates; ownership remains with the existing SQM setup.

15 — Worked example: why a 200 Mbps shaper currently stays at 200

src/controller.c:update_direction:555 src/controller.c:upward_factor:372 src/controller.c:scale_rate:21
Open SVGDOT source
Important behavior and caveats
  • This follows the current code and the supplied beta log example: achieved ≈153.199 Mbit/s, desired=200 Mbit/s, average delay ≈13.608 ms, no delayed samples.
  • 153.199/200 ≈76.6%, above default high_load_thr=75%. Delay is clear because delayed_count=0 (<3).
  • A fresh sample permits an upward factor near 1.032, but the result is clamped to max=200 Mbit/s. The shaper therefore remains at 200.
  • The controller does not infer a 175 Mbit/s capacity and subtract 5 Mbit/s. Doing that directly from each achieved sample would risk repeated downward ratcheting.
